# w16

**a `/bin` program.**

**Category:** Processes and programs

## Synopsis

```
w16 FILE [ARGUMENT...]
w16 --info FILE
w16 --check FILE
w16 --fonts
w16 --sounds
w16 --why CALL
```

## Options

- `-i`, `--info` -- print the program's segments and the functions it
  imports, and its resources, instead of running it.
- `-c`, `--check` -- list what the program imports, which of it `w16`
  has and what each is for, and print its description and icon, instead
  of running it: what Retro Launcher reads, so the launcher
  never parses a program itself. An import is a line
  `call missing USER.1 MessageBox Dialogs` (or `call has ...`), the
  name `?` when w16 knows none. A **stand-in** -- a call w16 answers
  without doing what Windows did, a Help file that is not shown or a
  printer that is not there -- is `call partly USER.171 WinHelp Dialogs`,
  then a tab and what w16 does; `has N` counts stand-ins too, and
  `partly N` says how many of them there are. A function imported **by
  name** that w16 cannot number -- one from the program's own DLL, or a
  name its tables lack -- is `call missing RASAPI.0 Name Other`, ordinal 0,
  each once: `imports N` counts exactly the `call` lines. A file that is no Windows
  3.x program says what it is instead -- `foreign a DOS program`,
  `foreign a 32-bit or 64-bit Windows program` -- before its `error`.
- `-f`, `--fonts` -- list Windows 3.11's own fonts found in drive C:'s
  `WINDOWS\SYSTEM` (`font FILE POINTS PIXELS WEIGHT`, a tab, the face),
  then a sample of each face as rows of 0s and 1s (`sample W H`, a tab,
  the face): what the launcher's Options show. Read in w16's sandbox, as
  `--check` reads a program.
- `-s`, `--sounds` -- list each sound event drive C:'s `WINDOWS\WIN.INI`
  names in its `[sounds]` section (Windows 3.11's seven when it has
  none), one line each: `sound`, then tab-separated its WIN.INI name
  (`SystemAsterisk`), what 3.1 called it, the file named, the file that
  plays, `found`, `missing` or `none` (not named), and toy-os's own sound
  for it -- as the `win311` setting would play, whatever `sounds` says:
  what the launcher's Options > Sound shows. Read in w16's sandbox.
- `-w`, `--why CALL` -- say what CALL (`USER.121`, as `--check` names
  it) does on Windows 3.1 and how w16 answers it; for a stand-in, also
  why it stops there, what a program may notice and what would make it
  whole. The text is CALL's section of the *Windows calls w16 answers*
  page (`doc calls`, or Help; `doc stand-ins` has the stand-ins alone),
  which Retro Launcher's **About** and **Why?** open too. For a call w16
  does NOT answer it says what the call does on Windows 3.1, why w16
  does not do it yet and which of Windows 3.11's own programs import it
  (*Calls w16 does not answer yet*, `doc missing`, what Retro Launcher's
  **What?** opens); a missing call with no text written gets what is
  known of it -- its kind, or for an export with no name, that it is a
  DLL's own.
- `-t`, `--trace FILE` -- write every Windows call the program makes to
  FILE as it makes it: the function, its argument words and where it was
  called from, then what it answered (`= DX:AX`) -- Wine's `+relay`; DOS
  calls (INT 21h), each `_fpMath` function with the x87's status word, and
  each floating-point exception handed to the program (INT 75h) too. How
  a program's next missing piece is found when the stop alone does not
  explain it.
- `-h`, `--help` -- the options.

## Description

Runs a 16-bit Windows (Windows 3.x) program in a window of its own. The
program's code runs on an emulated 286 inside `w16`, and the Windows
functions it calls -- KERNEL, USER, GDI -- are `w16`'s own; the window
looks as it did on Windows 3.1, caption and frame included, and moves,
resizes and closes like any other. The plan, and why the CPU is emulated
rather than run natively, is `docs/w16-design.md` in the source tree.

```
/$ w16 /usr/share/w16/hello.exe
```

What follows FILE is the program's command line, as Windows passed it --
most often a document to open. A toy-os path in it becomes the DOS path
the program can open, on drive Z: (below), and DOS's 126 characters are
the most it may be:

```
/$ w16 /home/Win16/NOTEPAD.EXE /tests/sample.txt
```

**Only a few functions exist so far.** A program that calls one that
does not -- or that faults -- stops with Windows 3.1's Application Error
box in its window, and when that is closed `w16` ends with SIGABRT and a
crash report whose message names why: the call, or the fault, where it
happened (segment:offset) and the registers. The desktop's crash notice
and `crashlog` lead with it, and stderr gets the same line:

```
w16: /usr/share/w16/fault.exe: Windows call failed at 1:0144 -- USER.7 (ExitWindows) is not implemented
```

`/usr/share/w16/fault.exe` does both on purpose: a click is a general
protection fault, a right click calls ExitWindows. `/usr/share/w16/gdi.exe`
draws with resources, both heaps, GDI's bitmaps, pens and brushes, a
timer, a metafile played scaled, a clip rectangle and a polygon.
`/usr/share/w16/dialog.exe` has a menu bar, a dialog with an edit field, a
message box and an About box; `/usr/share/w16/opendlg.exe` opens the Open
dialog on a template of its own three times and writes what it saw to
`OPENDLG.INI`; `/usr/share/w16/popup.exe` opens a red popup the size of
the screen over its main window, gone on a click. Of real programs (bring your own copies),
Windows 3.11's Minesweeper, Notepad, Solitaire, Hearts, Write and
Paintbrush run -- Write with its TrueType fonts and the pictures in a
document, drawn but not editable; Paintbrush draws, fills, writes text,
picks, copies and pastes, and saves and opens .BMP files in its own Save
As and Open dialogs (a program's own dialog template, built from its
resource). View Picture covers the whole screen, the picture at the
program's scale and centred on black, until a click or a key; Copy puts
the picture on the clipboard as a bitmap and a metafile; the Text tool
has a blinking caret.

A whole Windows 3.11 folder as drive C: works too. Its `NETAPI.DLL`, the
Workgroups network layer, is declined (`LoadLibrary` answers "not there"):
it talks to a real-mode NetBIOS through DOS memory, which w16 has nothing
behind, so Hearts plays alone, as on a folder without it.

Minimize, maximize and the control menu work as on 3.1 (a click on the
control-menu box or Alt+Space opens it, a double click on the box
closes, a double click on the caption maximizes); Move and Size are grey
until toywm can run a drag from the keyboard.

**Menus and dialogs** are drawn as 3.1 drew them. A program's menu bar
sits under its caption: a click on a title, Alt and the title's letter,
or F10 opens it, the arrows move along it, and its shortcuts
(TranslateAccelerator) work while it is closed. A dialog -- DialogBox
from the program's DIALOG resource, MessageBox, the About box -- is a
window of its own above the program's, which waits for it: Tab moves
between its fields, Enter is the default button, Esc is Cancel, and a
field's underlined letter goes to it. Its controls -- push buttons, check
boxes, radio buttons, group boxes, labels, edit fields, list boxes and
drop-down boxes -- are w16's own, and so are a program's: its main window
may hold them as children, as Notepad's text is an edit field filling
it. A program's Help opens nothing yet: a box says its .HLP file cannot
be shown.

**Files and the common dialogs.** A program sees drive C:, its Win16
folder (`drive_c` below); D: to Y:, each a folder when one is set
(`drive_d`..`drive_y`, Options > Drives); and Z:, the whole toy-os tree
-- so `/tests/sample.txt` is `Z:\tests\sample.txt` -- and starts in the
folder it was run from. A path is shown on the drive whose folder holds
it most closely. A drive under `/home` can be written, as Z: can there;
one elsewhere is read-only (the sandbox below). Names match without case, as DOS's did. Open and Save
As are Windows 3.1's own dialog (file list, folders, file types,
drives), Find is its modeless Find, and Print says there is no printer.
Of real programs, Windows 3.11's Notepad opens, edits, finds, word-wraps,
cuts and pastes through the toy-os clipboard, and saves. Text is in the
System font, or -- where a program asks for a fixed-pitch one, as
Notepad does -- DejaVu Sans Mono Bold, standing in for Fixedsys; an edit
field's caret blinks and the pointer over it is the I-beam.

`--info` reads an NE executable and prints what it holds: the module
name, the entry point and stack, the modules it imports from, each
segment, and each relocation -- an import is named, so the list of
`import` lines is the list of Windows functions the program needs.

```
/$ w16 --info /usr/share/w16/hello.exe
module HELLO
entry 1:0000 stack 2:0000 autodata 2 heap 1024 stacksize 4096
imports KERNEL USER GDI
...
  reloc 0001 src 3 import KERNEL.91 (InitTask)
  ...
```

**The file is treated as hostile, and so is its code.** Before reading a
byte, `w16` gives up all it will not need (`pledge`/`unveil`), and it
refuses to run if it cannot: it keeps reading the tree (drive Z:),
writing only under `/home`, drive C: and `/var/lib/win16`, and keeping
the clipboard and what a window needs -- a program can read the
system's files but change only the user's. A malformed
file is refused with the check that failed (`w16: FILE: a segment lies
outside the file, or too many segments`), never guessed at; a program
that reaches outside its own memory stops with a fault and where it
happened.

## Settings

`/etc/win16.conf` holds the defaults, and `/etc/win16/<program>.conf`
(the program's path with `/` made `_`:
`/etc/win16/usr_share_w16_gdi.exe.conf`) overrides any of the keys below
from `scale` to `drive_c` for that program alone. The Retro Launcher
app edits both: Options for the defaults, the details panel for the
selected program (its Drive C: as the default, the folder the program is
in, or one chosen).

| Key | Values | |
|---|---|---|
| `scale` | `auto` `1` `1.25` `1.5` `1.75` `2` `2.5` `3` | how big; `auto` is the step nearest the screen's width over 1280 (1920 wide: 1.5) |
| `method` | `sharp` `pixels` `smooth` | how a scale between whole steps spreads a pixel: `sharp` doubles and then smooths down (even, crisp), `pixels` keeps hard but uneven pixels, `smooth` blends (even, soft) |
| `frame` | `win31` `desktop` | Windows 3.1's frame, drawn by w16, or toywm's |
| `version` | `3.10` `3.11` `3.00` | what GetVersion answers. `3.10` is the default because it is what real Windows for Workgroups 3.11 answers (measured; `3.11` names the product, not the kernel), so `3.11` is only for a program that insists on it |
| `on_fault` | `box` `report` | the Application Error box, or straight to the crash report |
| `trace` | `on` `off` | `--trace` to `/var/lib/win16/<program>.trace` |
| `fonts` | `win311` `standin` | whose fonts a program's text is drawn in: Windows 3.11's own `.FON` files from drive C:'s `WINDOWS\SYSTEM` where they are there (each missing one falls back), or toy-os's stand-ins (Liberation, DejaVu) |
| `sounds` | `win311` `toyos` `off` | whose sounds a program's events play (MessageBeep, sndPlaySound's aliases): the file drive C:'s WIN.INI `[sounds]` names where it is there (else toy-os's), toy-os's own, or none; a program's own WAVs play with either of the first two |
| `help` | `viewer` `winhelp` | what a program's Help opens in: toy-os's Help Viewer, or Windows' own WINHELP.EXE run under w16 when drive C: has it (in WINDOWS or the root) -- the Help Viewer when it does not. WINHELP.EXE is told the topic a HELP_CONTEXT number or a HELP_KEY keyword names, but not a HELP_COMMAND macro |
| `colors` | `256` `16` | how many colours the display has: 256 (the default), or Windows 3.11's 16-colour VGA -- GetDeviceCaps says 16 colours on 4 planes, a brush of any other colour is dithered exactly as 3.11's VGA driver dithered it (measured on the reference), and a pen, text or pixel takes the nearest of the 16 |
| `drive_c` | a folder | drive C:, `/home/Win16`; INI files named without a path are in its `WINDOWS` |
| `drive_d`..`drive_y` | a folder, or empty | drives D: to Y:, the same for every program |
| `from_files` | `run` `check` `ask` `show` | what opening a program in the File Manager does: run it, run it unless calls it uses are missing (`check`, the default; then the run card), always show the run card, or show it in the launcher |
| `add_folder` | `on` `off` | a program run from the File Manager adds its folder to the launcher's list |
| `sound_drv` | `on` `off` | SOUND.DRV's notes played (Minesweeper's music), or a voice refused |
| `folders`, `folderN`, `folderN_name` | a count, folders, names | where the launcher looks for programs, as many as there are, in its sidebar's order; a name is what the sidebar calls it (empty: the folder's own). A file from before the count (`folder1`..`folder8`) still reads |

The launcher lists programs from its folders, one sidebar row each. The
Folder menu, or a folder's right-click menu, adds a folder, changes it
to another, renames its row, moves it up or down, or takes it off the
list; Options > Folders does the same as a list, applied on OK, and
Options > Drives sets drive C: and D: to Y:, saying what C: holds
(`WINDOWS`, COMMDLG.DLL, its fonts) and how many programs the others do.

Each run records how it ended in `/var/lib/win16/<program>.last`
(`ended`, or `stopped` and why), which the launcher shows.

A program's tile says how far w16 runs it -- `Runs`, `Runs · 10 partly`
when some calls are stand-ins, `3 missing` -- and its details panel
splits the calls it imports into Work, Partly and Missing on one bar,
with the stand-ins listed by what w16 does for them.

Each call w16 answers has an **About** cell on its row in the calls
window, and each stand-in a **Why?** -- there, and as a link beside it in
the details panel's "Partly there" list (Enter on a row does the same).
It opens a window with the call's section of the calls page: what
Windows 3.1 did and what w16 does -- the same text `w16 --why` prints.

The panel's **Missing calls...** button (Program > Calls it imports...)
opens a window listing every call the selected program imports: module,
ordinal, function, what it is for, its status (Works, Partly, Missing)
and what w16 does for it. Chips narrow it by status and by module; it
opens on Missing, else Partly, else All. A search, Copy and Save as text
work on the rows shown. `retrolauncher --calls FILE` opens it directly.

**From the File Manager.** Opening an `.exe` there runs `retrolauncher FILE`,
which does what `from_files` says. The run card (the one a script gets,
in its Windows-program face) names what w16 lacks of the program --
`Missing: ExitWindows`, each stand-in and what w16 does for it -- with
Show calls, Settings... (the launcher, the program selected), Cancel and
Run, and "Do not ask again", which sets `from_files` to `run`. A file
that is no Windows 3.x program gets the card saying what it is ("a DOS
program") and that it cannot run here. The File Manager's right-click
menu adds **Show its calls** and **Show in Retro Launcher** under Open
(`retrolauncher --show FILE`, which lists the program's folder if it is not
already), and its details pane and Properties show `Program` and `Runs`
(`retrolauncher --details FILE`) -- both declared in the launcher's desktop
entry (`data/wm/applications/README.md`, Actions and X-Details).

```
/$ write /etc/win16/usr_share_w16_gdi.exe.conf scale=2
/$ w16 /usr/share/w16/gdi.exe
```

**Windows 3.11's own fonts and pictures.** Copy your own Windows 3.1
installation's `SYSTEM` folder (or just its `.FON` files and
`COMMDLG.DLL`) to `/home/Win16/WINDOWS/SYSTEM` and w16 draws with them:
the System, Fixedsys and MS Sans Serif fonts -- and Courier, MS Serif,
Small Fonts and the rest for a program's CreateFont -- and the Open
dialog's folder and drive pictures. Without them it draws its own. The
launcher's Options > Display shows which fonts it found, with a sample of
each; the Fonts setting (there, and per program in the details panel)
turns them off. No Microsoft file is part of toy-os.

**Sound.** A program's sounds go through `soundd`, named in the Volume
panel by the program's title (`Hearts`) so it can be turned down on its
own: its own WAV files and resources (sndPlaySound), MessageBeep as the
Asterisk, Exclamation, Critical Stop or Question event, and SOUND.DRV's
notes as a square wave. An event plays the file WIN.INI's `[sounds]`
names when drive C: has it -- copy your own Windows 3.1 `WIN.INI` and
`.WAV` files to `/home/Win16/WINDOWS` -- and toy-os's chime otherwise.
Options > Sound in the launcher lists each event with a Play button;
the Sound setting per program is in its details panel.
`/usr/share/w16/sound.exe` plays one of each and exits.

`/usr/share/w16/` holds sample programs, built from source when the
system is built; no Microsoft program ships with toy-os.

Exit status: the program's own, 1 the file was refused, 2 a usage error.
A program that faults, or calls a function w16 does not have, ends w16
with SIGABRT and a crash report that names why.
